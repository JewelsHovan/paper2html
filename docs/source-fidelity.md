# Source-preserving conversion

`paper2html process SOURCE --source-only -o paper.html` converts without constructing an AI provider, requiring an API key, calling a model, or generating mock annotations. Library cost is zero. Existing atomic output/no-clobber and source-protection rules apply. Without this flag, configured provider behavior remains; optional AI reading aids are separate from source content.

## Model and rendering contract

`NormalizedDocument` now has defaulted `original_html: str`, `source_assets: dict[str, bytes]`, and `page_assets: list[bytes]`. Bytes use the model's existing base64 JSON serialization. The arXiv adapter retains the `article.ltx_document` (body fallback) and image assets keyed by raw `img.src` / `object.data`; inline SVG keys are content hashes. External SVG objects use guarded ingestion fetches and validated rasterization, never active embedding. Ordinary SVG uses Cairo; supported static LaTeXML `foreignObject` labels use optional Playwright Chromium after strict geometry, span, MathML and CSS reconstruction. Static minipage tables/listings use reader-owned layout. Only the exact LaTeXML text/plain base64 listing-download affordance is validated and projected into inert text; no download URI or arbitrary link reaches Chromium. Nested scientific raster images are fetched through guarded ingestion, validated with aggregate byte/pixel caps, and supplied as canonical raster data URIs; the browser never fetches source image URLs. That browser has JavaScript disabled, no resource access and no publisher styles/fonts. Install with `uv sync --group browser && uv run playwright install chromium`. Missing backend or unsupported markup yields an explicit omission warning, not a label-free Cairo rendering. Rasterized labels (including their math) are visual figure content, not searchable article MathML. These browser-rendered diagrams have a deliberate white background so black labels remain readable in dark mode. Renderer-owned DOM measurement fits static minipage text/images to bounded boxes, measures all four edges, checks final containment and rejects unreadable shrinking outside the supported reflow profile. A narrowly identified one/two-minipage gray-frame profile with malformed label geometry can instead be reflowed into a bounded readable panel, explicitly labeled “Source panel reflowed for readability”; this changes layout, not scientific content. Before any reflow, a complete positive classification of the source SVG layer verifies precisely two/three closed, axis-aligned frame paths with bounded rounded corners, known gray/white/near-white paints, inert strokes, bounded outer/inset/header panels and no unclassified graphics. A renderer-owned marker is added only after full sanitization; extra rectangles, paths, strokes or unknown geometry never qualify. Listing lines preserve literal spaces/tabs and remove only exact terminal LaTeXML pretty-print newlines. Ordinary diagrams retain their original logical dimensions. Publisher JavaScript remains disabled; the measurement is renderer-owned DevTools evaluation. Browser operations have timeouts, but this is not a hard end-to-end time or memory sandbox. Ingestion and the adapter reuse the same validated inline SVG raster. All images in a figure can appear in the source view; the legacy normalized figure record retains its first image.

Original HTML is **untrusted**, not pre-approved output. The renderer reconstructs allowed article structure and native MathML in source order, strips annotations to avoid duplicate math, prefixes IDs/fragment links with `source-`, and prefixes classes with `src-`. Publisher CSS/JS, event attributes, active objects, forms, frames, resource URLs, and unsafe links are not emitted. Images are revalidated raster data URIs. External hyperlinks allow only HTTP, HTTPS and mailto; rendering performs no fetches. Missing images produce warnings and visible placeholders. Source-order rendering is the default when original HTML exists. Synthetic/library documents with empty original HTML and no page assets retain normalized rendering.

For PDF ingestion (including arXiv PDF fallback), the CLI **always** supplies bounded 150-DPI page rasters, including vector graphics, plus separate extracted searchable text and page navigation, with or without `--source-only`. PDF views retain the bibliographic title/authors/abstract header; native HTML uses its own front matter without duplication. This is explicitly labeled a **facsimile**, not structured mathematical reconstruction. Source-only skips fragment extraction; existing direct `from_pdf` calls remain compatible, with optional `page_assets` and `extract_images` arguments. `ingest_pdf(..., extract_figures=False)` can likewise skip unnecessary fragments.

Optional AI summaries, terminology, margin notes and figure explanations appear in separate labeled asides, never within original source content. When needed, vendored KaTeX renders math only in those asides and the PDF metadata header—not native article MathML or PDF text transcription. Native-source-only output does not load KaTeX unnecessarily.

## Limits and limitations

Source HTML is bounded to the ingestion body-byte budget, 200,000 nodes and 128 HTML levels; MathML retains the stricter fragment limits. Source assets and PDF page assets have an aggregate source-byte budget (128 MiB by default), plus existing per-image byte/pixel and PDF page limits. The CLI validates source rendering before constructing or running an AI provider. Oversized source/page assets and invalid PDF page assets produce a clear error with no provider calls and no output publication, preserving an existing destination even with `--overwrite`. Direct `render_html` independently validates and fails closed before publication. Neither path silently falls back to an incomplete normalized article. Invalid individual images are explicitly omitted. Native PDF/SVG parsing retains existing in-process CPU-time limitations.

Wide source tables and equation tables—including tables inside LaTeXML phrasing wrappers—have keyboard-focusable horizontal scroll regions instead of widening the mobile page. Native article images can be clicked to show their original-sized raster within a local scroller. Nested scientific rasters, when supplied, are retained as separately validated original bytes and offered through inert full-resolution data-URI download links; they are not replaced by the lower-resolution composite alone. Rendered raster URI bytes are budgeted by actual emitted occurrence, and source budget failures abort document rendering. Basic source emphasis, alignment and table rules use reader-owned CSS.

This preserves supported article content, not publisher typography: arbitrary CSS and unsupported elements are intentionally excluded. PDF text extraction order can be imperfect; the complete visual page is authoritative. Native MathML requires a supporting browser. No publisher scripts, remote fonts, or remote math scripts are needed for the source view.
